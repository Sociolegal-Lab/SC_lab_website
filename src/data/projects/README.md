# 專案資料維護說明

## 檔案結構

每個專案由這些檔案組成，**編號必須一致**：

| 檔案 | 必要 | 說明 |
| --- | --- | --- |
| `project_<編號>.json` | 必要 | 專案資料 |
| `project_<編號>.md` | 選用 | 專案內頁的詳細內容 |
| `project_<編號>.<圖片副檔名>` | 選用 | 封面圖，支援 png / jpg / jpeg / gif / webp |

## 展示順序（自動計算，不需人工維護）

順序由每個專案的 `duration` 依下列規則自動算出，程式碼在
[`src/utils/sortProjects.js`](../../utils/sortProjects.js)：

1. **結束時間越晚的排越前**，`ongoing` 視為最晚（進行中的專案排最前面）
2. 結束時間相同時，**開始時間越晚的排越前**
3. 兩者都相同時，**編號越大的排越前**

專案列表、首頁輪播、內頁的「上一篇／下一篇」全部套用同一套排序，所以三處順序一致。

目前算出的順序：

| 位置 | 專案 | duration |
| --- | --- | --- |
| 1 | project_9 | 2026-ongoing |
| 2 | project_5 | 2025–ongoing |
| 3 | project_6 | 2024–ongoing |
| 4 | project_7 | 2025 |
| 5 | project_1 | 2024-2025 |
| 6 | project_8 | 2022-2025 |
| 7 | project_2 | 2023 |

改動任何專案的 `duration` 之後順序會自動調整，不需要改任何清單。

## 要讓某個專案不顯示

把它的 `published` 設為 `false`（後台的「是否顯示」關掉即可）。
關閉後它不會出現在專案列表、首頁輪播，內頁的上下篇導覽也不會經過它，
直接輸入網址會看到「Project not found」。

目前 `project_4.json`（CrowdEyes）的 `published` 是 `false`，
它的 `duration` 也還是 `?`。要公開它，請先補上實際時間，順序才能正確計算。

## duration 的寫法

| 情況 | 寫法 |
| --- | --- |
| 進行中 | `2025-ongoing` |
| 已結束 | `2024-2025` |
| 單一年份 | `2025` |

現有資料混用了半角 `-` 與全角 `–`，排序時兩者視為相同，但**新增資料請統一用半角 `-`**。
無法判讀的寫法（例如 `?`）會被排到最後。

## 新增一個專案

新增仍需手動進行，因為一個專案橫跨三個檔案，後台一個畫面只對應一個檔案，
無法保證三者編號一致。

1. 準備 `project_<新編號>.json`，編號用目前最大號碼 +1，`published` 填 `true`。
2. 需要內頁就加 `project_<同編號>.md`，需要封面圖就加 `project_<同編號>.<副檔名>`。
3. 執行 `npm run validate-json` 與 `npm run verify_project_data_filename` 確認格式無誤。

順序會依 `duration` 自動排入正確位置，不需要再做任何事。
