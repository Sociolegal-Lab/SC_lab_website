# 網站內容管理後台 使用說明

這份說明分兩部分：

- **第一部分**給管理者（只需做一次的設定）
- **第二部分**給實驗室成員（日常更新網站用）

---

# 第一部分：管理者的初次設定

## 這個後台是什麼

網站的文字和照片都存放在 GitHub 上的檔案裡。後台提供一個**填表單的畫面**，
成員填完按儲存，系統會自動幫他們改檔案，網站接著自動重新產生。

成員不需要學 git，也不會看到任何程式碼。

## 需要注意的事

**後台是第三方託管服務（Pages CMS）。** 使用它必須授權它讀寫這個 repo。
授權的意思是：這個服務能代替你們修改 repo 的內容。如果你們不希望把寫入權
交給外部服務，就不要走這條路，改用第二部分最後提到的替代方式。

因為 repo 屬於 `Sociolegal-Lab` 這個組織，**組織的管理者可能需要先批准**
這個第三方應用程式，成員才能使用。

## 設定步驟

1. 前往 <https://app.pagescms.org> ，用 GitHub 帳號登入。
2. 授權它存取 `Sociolegal-Lab/SC_lab_website` 這個 repo。
   （如果卡在「需要組織批准」，請組織管理者到 GitHub 的
   Settings → Third-party Access 批准。）
3. 登入後應該會看到兩個編輯畫面：**成員名單**、**最新消息**。
   這是由 repo 根目錄的 `.pages.yml` 決定的。
4. 請成員各自申請 GitHub 帳號，然後把他們加入這個 repo 的協作者
   （GitHub repo → Settings → Collaborators）。**只有 repo 的協作者能編輯。**

## 儲存之後會發生什麼

```
成員在後台按「儲存」
        ↓
內容被寫進 main 分支
        ↓
GitHub Actions 自動建置網站（約 2～5 分鐘）
        ↓
官網更新完成
```

網站是「事先產生好的靜態網頁」，不是即時讀資料庫，所以**改完需要等幾分鐘**才會看到。

## 送出前的自動檢查

每次內容變動都會自動檢查格式，包含：

- 必填欄位有沒有漏
- 成員編號有沒有重複（重複會讓照片、連結對到錯的人）
- 日期格式對不對

檢查不通過會在 GitHub 上顯示紅色錯誤。

# 第二部分：成員的操作方式

## 開始之前

你需要一個 GitHub 帳號，並且已經被加入實驗室的 repo。如果打不開後台或看不到
編輯畫面，表示還沒被加入，請找管理者。

## 登入

1. 打開 <https://app.pagescms.org>
2. 按 GitHub 登入
3. 選擇 `SC_lab_website`
4. 左邊會看到「成員名單」和「最新消息」

## 新增一位成員

1. 點左邊的「**成員名單**」
2. 按「**Add an entry**」（新增一筆）
3. 填寫欄位：

| 欄位 | 怎麼填 |
| --- | --- |
| 目前狀態 | 選「現任成員」 |
| 中文姓名 | 例如：王小明 |
| 英文姓名 | 例如：Hsiao-Ming Wang（**網頁上顯示的是這個**） |
| 頭銜 | 例如：Master's student |
| 照片 | 按上傳，選你的照片檔 |
| Email | 沒有可以留空 |
| 卡片列點 | 卡片上的短列點，一行一個項目；沒有就留空 |
| 自我介紹 | 較長的一段介紹 |
| 社群連結 | 有的填，沒有的留空 |
| 編號 | **看現有名單裡最大的號碼，然後 +1**。不可以跟別人一樣 |

4. 按「**Save**」（儲存）
5. 等幾分鐘，重新整理官網就會看到

## 修改自己的資料

1. 點「成員名單」
2. 在清單中點自己的名字
3. 改完按「Save」

## 畢業或離開實驗室

**不要刪除自己的資料。** 只要做一件事：

1. 點「成員名單」→ 點自己的名字
2. 把「**目前狀態**」從「現任成員」改成「**已離開（畢業／離職）**」
3. 按「Save」

你的資料會自動從 `CURRENT MEMBERS` 移到 `FORMER MEMBERS`，
照片和介紹都會跟著過去，不需要重新填寫。

## 真的要移除一個人

在清單中該筆右邊的選單選「Delete」。

**注意：這會把資料永久刪掉。** 如果只是畢業，請用上面的改狀態，不要刪除。

## 新增一則消息

1. 點左邊的「**最新消息**」→「Add an entry」
2. 填標題、日期、內容，有相關連結就填
3. 編號填目前最大號碼 +1
4. 按「Save」

**消息的封面圖沒辦法在這裡上傳。** 封面圖是靠檔名對應編號的：
如果你的消息編號是 `9`，圖片就要命名成 `9.jpg` 放進 `src/data/news/` 資料夾。
這一步需要請管理者或熟悉 GitHub 的人幫忙。

## 常見問題

**Q：我改完了，但官網沒變？**
A：網站需要幾分鐘重新產生。等 5 分鐘再重新整理。如果超過 10 分鐘還沒變，
可能是格式檢查沒通過，請找管理者看 GitHub 上有沒有紅色錯誤。

**Q：照片上傳了但沒顯示？**
A：確認檔案是圖片格式（jpg、jpeg、png、gif、webp），而且檔名不要用空白或特殊符號。

**Q：編號要填什麼？**
A：看現有名單最大的號碼 +1。**絕對不要跟別人重複** —— 重複會讓照片對到錯的人。
如果不小心重複了，系統會擋下來並顯示錯誤。

**Q：我改錯了，可以回復嗎？**
A：可以。所有修改都有完整紀錄，找管理者可以還原到任何一個之前的版本。

**Q：專案（Projects）為什麼不能在後台改？**
A：專案的顯示順序是人工排定的（哪個排最前面、哪些不顯示），而且每個專案由
好幾個檔案組成。放進後台會破壞這些設定，所以專案仍然由熟悉 GitHub 的人維護。

## 不想用第三方後台的替代方式

如果決定不授權外部服務，成員仍然可以直接在 GitHub 網站上編輯：

1. 打開 <https://github.com/Sociolegal-Lab/SC_lab_website>
2. 進入 `src/data/members/members.json`
3. 按鉛筆圖示編輯，照 `src/data/members/template.md` 的格式填
4. 送出 Pull Request，通過自動檢查後合併

這個方式不需要授權任何外部服務，但成員必須直接面對 JSON 格式。
